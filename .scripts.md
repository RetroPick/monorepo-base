# Operator guide: market launch from V1

This doc tells you **how to operate** RetroPick market flows using **[RETRODEPLOYER](scripts/RETRODEPLOYER)** from the monorepo root. All **prepare** calldata goes through the **local Go API** (`POST /api/v1/ops/tx/prepare`). Deeper product and contract context: [package/contract/.operator/.runbook.md](package/contract/.operator/.runbook.md), [package/contract/currentSmartContract.md](package/contract/currentSmartContract.md).

---

## 1. Where you run commands (always the V1 repo root)

Your shell **current working directory** must be the **V1** clone (the folder that contains `apps/`, `package/`, and `scripts/RETRODEPLOYER`).

```bash
cd ~/dev/Project/V1    # or your path to V1
```

- **Do not** use `./scripts/RETRODEPLOYER` from `package/contract` — that is a different `scripts/` tree and the file is not there.
- From elsewhere: `bash /path/to/V1/scripts/RETRODEPLOYER help`.

**Optional:** from the same root, `pnpm run retropick:deployer <args>` is the same as `bash ./scripts/RETRODEPLOYER <args>`.

## 2. How to run: from help to first open epoch (“deploy” the epoch on-chain)

End-to-end path from **discovering commands** to **submitting the `openEpoch` tx** (first epoch) for your prepared markets. Cwd = [§1](#1-where-you-run-commands-always-the-v1-repo-root).

### Easiest: one command (keystore + password only)

**Requires:** local **API** running ([§3](#3-set-up-before-you-operate)), [Foundry](https://book.getfoundry.sh) `cast`, and ETH on the keystore for gas.

```bash
cd ~/dev/Project/V1
./scripts/RETRODEPLOYER deploy-all
# or:  pnpm run retropick:deploy
```

You are prompted only for:

- **Keystore name** (default `testnet` — the name from `cast wallet list`)
- **Password** (hidden; if you press Enter, `cast` will ask per transaction instead; set a password to avoid 27 prompts)

**Defaults (override via env before running, or `package/contract/.env`):**

- `RPC_URL` from `.env` if set, else `https://sepolia.base.org`
- Staging: `.retropick-deploy/1-upinit` and `.retropick-deploy/2-open` (gitignored); override with `RETRODEPLOYER_WORK_DIR` or `deploy-all --work-dir /path`
- **Wait** 90s between the 18 txs and the open-epoch step (`RETRODEPLOYER_WAIT_SEC=120` if `openEpoch` reverts; increase if the chain is slow)
- **Epoch times** (unix): open ≈ now+2m, lock ≈ now+1h, resolve ≈ now+2h (in-script defaults)

**Steps inside `deploy-all`:** HTTP `prepare` 18 files → `cast send` ×18 → sleep → HTTP `openEpoch` ×9 files → `cast send` ×9.

| Step | Command | Purpose |
|------|---------|---------|
| **A. Help** | `./scripts/RETRODEPLOYER help` | Subcommands, env, `batch-send` / `prepare-open-all`. Same: `pnpm run retropick:deployer help` |
| **B. Menu (interactive)** | `./scripts/RETRODEPLOYER menu` | Picks: **Deploy all 9** (same as `deploy-all`), prepare, `batch-send`, `prepare-open-all`, `send`, etc. |
| **C. Prerequisites** | (see [§3](#3-set-up-before-you-operate)) | API up; [package/contract/.env](package/contract/.env) with `RPC_URL`, `CAST_ACCOUNT` before any **send** / **batch-send** |
| **D. Prepare (HTTP, no gas)** | e.g. `./scripts/RETRODEPLOYER prepare all` or `launch 01` per type; save one JSON per file | Produces `upsertTemplate` + `initializeMarket` (and optional `openEpoch`) calldata. Name files e.g. `01-up.json` / `01-init.json` … `09` (or use `order.lst`) — details in [§5](#5-how-to-run-a-standard-manual-market-type-0109) |
| **E. Broadcast upsert + init** | `./scripts/RETRODEPLOYER batch-send /path/to/dir` | Prompts before each tx (`y`, **`a`** = yes to all remaining, `q` quit). Use `--yes` only if you trust the dir. Runs **in order** (auto: per-type up then init, all types, then any `NN-open.json` in that dir). |
| **F. Wait (recommended)** | Explorer / `cast` | Confirm the **18** upsert+init txs (9 types × 2) are mined before opening epochs. |
| **G. Prepare open epoch (HTTP)** | `./scripts/RETRODEPLOYER prepare-open-all --out-dir /path --open-at S --lock-at S --resolve-at S [--epoch-id N]` | Same **unix** times for all nine slugs. Writes `01-open.json` … `09-open.json` |
| **H. Broadcast open epoch (on-chain)** | `./scripts/RETRODEPLOYER batch-send /path` | Prefer a **second** `batch-send` on a directory that has **only** the nine `NN-open.json` (or a short `order.lst`) so opens are not sent before inits land. A single 27-file dir works only if the first 18 txs are final |
| **I. Optional dry run** | `DRY_RUN=1 ./scripts/RETRODEPLOYER send /tmp/one.json` | Prints `target` / chain check; [broadcast](package/contract/scripts/market/broadcast-prepared-ops-tx.sh) does not `cast send` |

**Shorter path for one type with open in the same prepare run:**  
`./scripts/RETRODEPLOYER launch 01 open --open-at … --lock-at … --resolve-at …` → save the three JSON objects → `send` or `batch-send` that folder. See [§5](#5-how-to-run-a-standard-manual-market-type-0109).

**From zero (two folders — recommended)**

1. **API + .env** — [§3](#3-set-up-before-you-operate). Export or put in `package/contract/.env`: `API_URL` (if not default), `RPC_URL` (e.g. Base Sepolia), `CAST_ACCOUNT=testnet` (or your `cast wallet list` name).
2. **Prepare** — e.g. `./scripts/RETRODEPLOYER prepare all` and **save** each JSON from the log into `mkdir -p /tmp/rp` as `01-up.json`, `01-init.json`, … `09-up.json`, `09-init.json` (one object per file). Or `prepare` / `launch` per type. Do **not** create `01-open` yet.
3. **First broadcast — only upsert + init**  
   `CAST_ACCOUNT=testnet ./scripts/RETRODEPLOYER batch-send /tmp/rp`  
   Approve 18 transactions (or `--yes` if you are sure). **Wait** until a block explorer shows they succeeded (or at least the last one mined).
4. **Prepare open epoch (HTTP only)**  
   `mkdir -p /tmp/rp-open`  
   Pick times in **unix seconds** with `open < lock < resolve` and `lock` **after** `block.timestamp` (see contract: minimum deposit/lock window constants in `MarketEngineBase.sol`). Example:  
   `./scripts/RETRODEPLOYER prepare-open-all --out-dir /tmp/rp-open --open-at 2000000000 --lock-at 2000001000 --resolve-at 2000002000`
5. **Second broadcast — only opens**  
   `CAST_ACCOUNT=testnet ./scripts/RETRODEPLOYER batch-send /tmp/rp-open`  
   (Use a **separate** directory so you never “open-only” by mistake. If the batch warning appears, you skipped step 2–3 for that `templateId`.)

**Troubleshooting: `InvalidTemplate` (selector `0xec55b8cd`) on `openEpoch`**

- On the contract, `openEpoch` requires the template to exist and **[`initializeMarket` to have been executed](package/contract/src/engine/modules/MarketEngineCoreLifecycleModule.sol) (`ledger.initialized`)**. If you `batch-send` a folder with **only** `01-open.json`…`09-open.json` before steps 1–2 succeeded on that engine, the tx **reverts** with `InvalidTemplate` — this is the usual mistake.
- **Not** the same: wrong `RPC_URL` (different chain than `chainId` in the JSON) → often chain-id mismatch error from the script, not on-chain.
- If timing is wrong you get `InvalidTiming()`, not `InvalidTemplate`.

```bash
cd ~/dev/Project/V1
./scripts/RETRODEPLOYER help
# … prepare and save 18 files to /tmp/rp, then:
./scripts/RETRODEPLOYER batch-send /tmp/rp
# … after inits are mined, prepare and send opens as above
```

## 3. Set up before you operate

| Step | What to do |
|------|------------|
| API | In another terminal, run the Go API (e.g. `go run ./cmd/api` in `apps/backend`, default `http://127.0.0.1:8080`). Check: `curl -sS http://127.0.0.1:8080/api/v1/health` returns JSON. |
| Registry | The API’s `chainId` and `marketEngineProxy` come from [apps/backend/internal/registrydata/registry.json](apps/backend/internal/registrydata/registry.json). After a new deploy, update that file and rebuild or run a binary that includes it. |
| On-chain | You need a **deployed MarketEngine** (and often stake token). Cold deploy: [package/contract/scripts/deploy-testnet.sh](package/contract/scripts/deploy-testnet.sh) (see script header; Base Sepolia addresses in [package/abi/address.md](package/abi/address.md)). |
| Tooling | **Foundry** `cast` in `PATH` for `send` and for any manual `cast keccak` of template ids. **pnpm** is used for the monorepo ([AGENTS.md](AGENTS.md)). |
| Env file | [package/contract/.env](package/contract/.env) — RETRODEPLOYER loads it every run. Put here what you do not want to re-type: `API_URL` (optional; default is `http://127.0.0.1:8080` if unset), and for **`send` / `batch-send`**: `RPC_URL`, **`CAST_ACCOUNT`** = a real [Foundry keystore name](https://book.getfoundry.sh/reference/cast/cast-wallet) from `cast wallet list` (e.g. `testnet` — not a copy-paste placeholder like `your-foundry-keystore-name`). You can also use `ETH_KEYSTORE_ACCOUNT` or `DEPLOY_ACCOUNT` or `KEYSTORE_NAME` for the same string. Optional `ETH_PASSWORD` for non-interactive keystore. |
| Role | The keystore you use to **`send`** must have **admin** or **workerAuthority** on the engine for the deployment. |
| Chain match | The prepare JSON’s `chainId` / `target` should match the **RPC** you use for `send`, or set `SKIP_CHAIN_CHECK=1` if you are sure. |

## 4. What RETRODEPLOYER is

- **One entry** at the repo root: [scripts/RETRODEPLOYER](scripts/RETRODEPLOYER).
- It **delegates** to [package/contract/scripts/market/](package/contract/scripts/market/) (no duplicate HTTP/`cast` in the wrapper).
- **Default API:** `API_URL` from `.env` or `http://127.0.0.1:8080`.

### Command cheat sheet (cwd = V1 root)

| You want to… | Run |
|--------------|-----|
| See usage | `./scripts/RETRODEPLOYER` or `help` |
| TUI menu (bash `select`) | `./scripts/RETRODEPLOYER menu` |
| Prepare **upsert** for type 01–09 or a JSON path | `./scripts/RETRODEPLOYER prepare upsert 01` or `… upsert package/contract/.operator/upsert-params/01-direction.manual.json` |
| **Launch** = upsert + init for type 01–09 (and optional `open` epoch) | `./scripts/RETRODEPLOYER launch 01` or `… launch 01 open --open-at S --lock-at S --resolve-at S` (or set `OPEN_AT` / `LOCK_AT` / `RESOLVE_AT` with `open` and no flags) |
| Prepare **all nine** manual upserts (HTTP only) | `./scripts/RETRODEPLOYER prepare all` |
| **Generic** prepare (any whitelisted `function` name) | `./scripts/RETRODEPLOYER prepare fn <name> <args.json>` (paths can be under repo root) |
| **Broadcast** a saved prepare response | `./scripts/RETRODEPLOYER send /path/to.json` or `send -` (stdin) |
| **Batch-send** many files (prompts each; or `order.lst`) | `./scripts/RETRODEPLOYER batch-send /path/to/dir` or `… batch-send --yes /path/to/dir` |
| **Prepare openEpoch for all 9** (same unix times → `01-open.json`…`09-open.json`) | `./scripts/RETRODEPLOYER prepare-open-all --out-dir /tmp/rp --open-at S --lock-at S --resolve-at S` |
| pnpm | `pnpm run retropick:deployer help` |

**Compact JSON:** `PRETTY=0` on the environment when you run prepare-emit commands (propagates to children where applicable).

**On-chain you usually do three things in order:** (1) `upsertTemplate`, (2) `initializeMarket`, (3) `openEpoch` only if you need an epoch opened now — `launch` runs the prepare steps for 1 and 2, and 3 if you pass `open` and times. **Save** each API JSON to a file, then `send` each file in order.

**Automating broadcast and open (recommended):**

1. Save each prepare response as **one JSON object per file** under a directory, using a consistent name, e.g. `01-up.json` and `01-init.json` … `09-up.json` / `09-init.json` (aliases: `NN-upsert.json`, `NN-initialize.json`). Or add an **order.lst** file listing one path per line (in send order, `#` comments allowed).
2. From the V1 root: `./scripts/RETRODEPLOYER batch-send /path/to/dir` — you get a **prompt before each** `cast send` (answer `a` to approve all remaining, `q` to quit). `batch-send --yes /path/to/dir` sends every file without asking (CI / controlled environments only).
3. **After** those upsert+init txs are mined, prepare **openEpoch** for all nine: `./scripts/RETRODEPLOYER prepare-open-all --out-dir /path --open-at S --lock-at S --resolve-at S` (uses fixed upsert slugs in-repo to recover `templateId`). That writes `NN-open.json`. Put them in the **same** directory as the first batch (or a new dir), then `batch-send` again — with auto layout, the tool sends 01…09 up/init first and **appends** `01-open`…`09-open` if those files exist, so a folder with 27 well-named files can be sent in the correct order in one go **only** if you are sure the first 18 txs are confirmed before the nine opens (otherwise run `batch-send` twice: 18 files, then 9 open files, or use a partial `order.lst`).

The **menu** (`./scripts/RETRODEPLOYER menu`) also includes “Batch-send a directory” and “Prepare openEpoch for ALL 9 types” with the same prompts.

## 5. How to run a standard manual market (type 01–09)

**Types** `01`–`09` map to files under [package/contract/.operator/upsert-params/](package/contract/.operator/upsert-params/) (see §6).

**A. Prepare calldata (HTTP, API must be up)**

Option **one-shot launch** (prints two prepares; read stderr for `templateId` on `launch`):

```bash
./scripts/RETRODEPLOYER launch 01
```

Or **stepwise**: upsert, then init (or use `prepare fn` with your args):

```bash
./scripts/RETRODEPLOYER prepare upsert 01
# If not using "launch 01" for init, also:
./scripts/RETRODEPLOYER prepare fn initializeMarket package/contract/scripts/market/args/initialize-market.example.json
# Edit that JSON’s templateId if you are not copy-pasting from a prior run.
```

**With open epoch in the same chain of prepares:**

```bash
./scripts/RETRODEPLOYER launch 01 open --open-at 2000000000 --lock-at 2000001000 --resolve-at 2000002000
```

**B. Save outputs**  
Redirect or copy the JSON for each `prepare` response to files, e.g. `/tmp/upsert.json`, `/tmp/init.json`, `/tmp/open.json`.

**C. Broadcast (Foundry, funded key)**

```bash
./scripts/RETRODEPLOYER send /tmp/upsert.json
./scripts/RETRODEPLOYER send /tmp/init.json
# If you used launch … open:
# ./scripts/RETRODEPLOYER send /tmp/open.json
```

`RPC_URL` and `CAST_ACCOUNT` must be set in **`.env` or the environment** before `send` (see [§3](#3-set-up-before-you-operate)).

**D. Times in unix seconds** (for `open` / `openEpoch`): e.g. `date -d "2026-04-26 15:00:00" +%s` on Linux, or [package/contract/scripts/market/lib/unix-epoch.sh](package/contract/scripts/market/lib/unix-epoch.sh).

**E. After markets exist — lock / resolve (manual, until API supports single-epoch lock/resolve)**  
Use **`lockEpochsBatch` / `resolveEpochsBatch`** via `prepare fn` and [args](package/contract/scripts/market/args/) (one-element arrays), or `cast` + proxy ABI. See [ops_prepare.go](apps/backend/internal/api/ops_prepare.go) whitelist.

**Corridor (08) / Cascade (09):** set `eventOracle` to a real `TrustedReporterAdapter` in the JSON before on-chain success; placeholder values are intentional. See [currentSmartContract.md](package/contract/currentSmartContract.md) and [address.md](package/abi/address.md).

**Prepare all nine types (generates many HTTP prepares; use for dev smoke):**

```bash
./scripts/RETRODEPLOYER prepare all
# Optional: per-type on-disk output (script used by “prepare all” path):
OUT_DIR=/tmp/retropick-prepare PRETTY=0 ./scripts/market/prepare-all-manual-types.sh
```

## 6. The nine manual types (RETRODEPLOYER `01`–`09`)

Enum order: [MarketTypes.sol](package/contract/src/types/MarketTypes.sol) (`Direction` = 0 … `Cascade` = 8). **Rolling** training JSONs: `01-direction.rolling.json`, `02-threshold.rolling.json` only (use `prepare upsert` with those paths; rolling rules in [.launcMarket.md](package/contract/.operator/.launcMarket.md)). Rolling is incompatible with Convergence, Composite, Corridor, Cascade.

| # | Type | Manual JSON | Notes |
|---|------|-------------|--------|
| 01 | Direction | `01-direction.manual.json` | Binary; `thresholdRule` 0 (None) |
| 02 | Threshold | `02-threshold.manual.json` | `thresholdRule` 1, `absoluteThresholdValueE8` |
| 03 | RangeClose | `03-rangeclose.manual.json` | 3 outcomes; `rangeBoundsE8` |
| 04 | Velocity | `04-velocity.manual.json` | 3 outcomes; `velocityBoundsE4` + `rangeBoundsE8` |
| 05 | Ladder | `05-ladder.manual.json` | `ladderBoundsE8` + `ladderPayoutWeightsBps` |
| 06 | Convergence | `06-convergence.manual.json` | Two feed ids, `spreadToleranceBps` |
| 07 | Composite | `07-composite.manual.json` | `compositeFeedIds`, `compositeConditions`, `compositeLogic` |
| 08 | Corridor | `08-corridor.manual.json` | `TrustedReporter` — set `eventOracle` for real use |
| 09 | Cascade | `09-cascade.manual.json` | Same; `cascadeDownward`, monotonic `rangeBoundsE8` |

Oracle examples often use a Chainlink-style 32-byte `oracleFeedId` (padded); multi-feed types need **distinct** ids.

## 7. Rolling path (4b) — short

1. `upsertTemplate` with a **rolling** JSON (e.g. `01-direction.rolling.json` — `executionMode` 1, interval &gt; 0, buffer &lt; interval).  
2. `initializeMarket`  
3. `genesisStartRolling` → `genesisLockRolling` in the runbook window  
4. Steady: `executeRollingRound` or `executeRollingRoundBatch` (see [execute-rolling-round-batch.example.json](package/contract/scripts/market/args/execute-rolling-round-batch.example.json))

## 9. Reference: what the API can prepare

**Endpoint:** `POST ${API_URL}/api/v1/ops/tx/prepare` — body `{ "function": "<name>", "args": [ … ] }` (decoder: [ops_prepare.go](apps/backend/internal/api/ops_prepare.go)). Typical response: `target`, `chainId`, `calldata`, `function`, `validationChecklist`, `runbookRef`.

| `function` | Args (summary) |
|------------|----------------|
| `upsertTemplate` | one `UpsertTemplateParams` object ([ethops](apps/backend/internal/ethops/upsert_template_params.go)) |
| `initializeMarket` | `[ templateId ]` |
| `openEpoch` | `[ templateId, epochId, openAt, lockAt, resolveAt ]` |
| `openEpochsBatch` | five parallel arrays |
| `lockEpochsBatch` | `templateIds[]`, `epochIds[]` |
| `resolveEpochsBatch` | `templateIds[]`, `epochIds[]` |
| `genesisStartRolling` / `genesisLockRolling` | `[ templateId ]` |
| `executeRollingRound` | `[ templateId ]` |
| `executeRollingRoundBatch` | one array of `templateId` hex strings |
| `pauseProgram` | `[ bool ]` |

There is **no** single-epoch `lockEpoch` / `resolveEpoch` in the whitelist; use the **batch** forms or `cast` + ABI.
