## What happened

Your flow tried to advance/lock an epoch.

During the dry-run precheck, RetroDeployer probably simulated the transaction with `eth_call` before actually broadcasting. That is good behavior because it prevents wasting gas.

The call path likely looked like this:

```text
RETRODEPLOYER advance
  → MarketEngine.lockEpoch / executeRollingRound
    → OracleAdapter.read()
      → ChainlinkAggregator.latestRoundData()
        → revert("No access")
```

So the engine tried to read the configured Chainlink feed through your adapter, but the feed rejected the call.

The feed is probably a gated/testnet/feed-proxy address. Some Chainlink feeds have access checks like:

```solidity
hasAccess(user, calldata) || tx.origin == user
```

That means:

| Caller type              | Result   |
| ------------------------ | -------- |
| EOA reads feed directly  | allowed  |
| Your contract reads feed | rejected |
| Engine → adapter → feed  | rejected |
| Dry-run simulation       | rejected |

So even though the feed address may be valid, it is **not usable by your smart contract**.

That is why your dry-run failed before keystore unlock:

```text
broadcast aborted before keystore unlock
```

That part is good. It means the script protected you from signing and sending a transaction that would revert anyway.

# How to verify before retrying lock

You want to verify **contract-readability**, not just that the feed exists.

A bad test is:

```bash
cast call <feed> "latestRoundData()(uint80,int256,uint256,uint256,uint80)" --rpc-url $RPC_URL
```

Because that may work from your EOA/static call context but still fail from your adapter/engine.

A better test is to call your adapter method directly if you have one, for example:

```bash
cast call <ADAPTER_ADDRESS> \
  "read(bytes32)(int256,uint256,uint256)" \
  <ORACLE_FEED_ID> \
  --rpc-url $RPC_URL
```

Or if your adapter uses feed address directly:

```bash
cast call <ADAPTER_ADDRESS> \
  "latestPrice(address)(int256,uint256,uint256)" \
  <FEED_ADDRESS> \
  --rpc-url $RPC_URL
```

Use your actual adapter function name.

The key is:

```text
adapter → feed
```

must work, because that is what the engine uses.

## Why this breaks lock/advance

In a Pancake-style / RetroPick-style market, locking needs an oracle checkpoint.

For a Direction market:

```text
lockEpoch writes checkpoint A
resolveEpoch writes checkpoint B
winner = checkpointB > checkpointA
```

So if the oracle read fails at lock time, the epoch cannot safely lock.

That is why your script says:

```text
advance: lock failed for epoch=1
```

The epoch lifecycle is blocked because the oracle checkpoint cannot be read.
